# DocuChat — RAG Chatbot over Custom Documents

![Python](https://img.shields.io/badge/python-3.10%2B-blue)
![LangChain](https://img.shields.io/badge/langchain-core-green)
![Vector DB](https://img.shields.io/badge/vector--db-FAISS-orange)
![License](https://img.shields.io/badge/license-MIT-lightgrey)

A **Retrieval-Augmented Generation (RAG)** chatbot that answers questions strictly from
your own documents. Ask about a company handbook, product FAQ, or any `.md` / `.txt` /
`.pdf` files you drop into `data/sample_docs` — every answer comes with **source
citations**, and the bot refuses to answer when the documents don't contain the answer.

## Problem statement

LLMs hallucinate when asked about private or niche knowledge (internal wikis, product
docs, policies). DocuChat grounds every answer in retrieved document chunks, so responses
are **verifiable**: each fact cites the file it came from, and out-of-scope questions get
an honest "I don't know" instead of a made-up answer.

## Features

- 📥 Ingestion pipeline: load `.md` / `.txt` / `.pdf` → recursive chunking → OpenAI embeddings → FAISS index
- 💬 Grounded Q&A: top-k retrieval + a strict system prompt (answer *only* from context, cite sources)
- 🔍 Source citations on every answer (`[company_handbook.md]`)
- 🛡️ Anti-hallucination guardrail: refuses unknown questions instead of inventing facts
- 📊 `evaluate` command: runs a fixed question set and writes a markdown report
- ⚙️ Everything tunable via `.env` (models, chunk size, top-k)

## Architecture

```
┌──────────────┐      ┌──────────────┐      ┌──────────────┐
│  Documents   │─────▶│   Chunking   │─────▶│  Embeddings  │
│ .md/.txt/.pdf│      │  recursive,  │      │  OpenAI      │
└──────────────┘      │  800 chars,  │      │  text-emb-3  │
                      │  120 overlap │      │  -small      │
                      └──────────────┘      └──────┬───────┘
                                                 │ ingest
                                                 ▼
┌──────────────┐      ┌──────────────┐      ┌──────────────┐
│    Answer    │◀─────│  Prompt +    │◀─────│    FAISS     │
│ + citations  │      │ GPT-4o-mini  │      │  index       │
└──────────────┘      │ (temp = 0)   │      │  top-k = 4   │
                      └──────────────┘      └──────────────┘
                                                 ▲
                                          ┌──────────────┐
                                          │ User question│
                                          └──────────────┘
```

**Flow:** `ingest` builds the index once. At query time the question is embedded, the
4 most similar chunks are retrieved, stuffed into a grounded prompt, and GPT-4o-mini
generates a cited answer. Retrieval and generation are kept explicit (no hidden chain
magic) so the pipeline is easy to debug and explain.

## Installation

```bash
git clone <your-repo-url> docuchat-rag
cd docuchat-rag
python -m venv .venv && source .venv/bin/activate   # Windows: .venv\Scripts\activate
pip install -r requirements.txt
cp .env.example .env   # then add your OPENAI_API_KEY
```

You need an [OpenAI API key](https://platform.openai.com/api-keys) for embeddings and chat.

## Usage

```bash
# 1. Build the vector index from data/sample_docs
python main.py ingest

# 2a. Chat interactively
python main.py chat

# 2b. Ask a single question
python main.py ask "What is the remote work policy?"

# 3. Run the evaluation question set
python main.py evaluate
```

Example session:

```
You: What is included in the Pro tier?
DocuChat: The Pro tier costs $99/month and includes unlimited dashboards, 10 data
sources, 13-month data history, anomaly alerts, Slack integration, and priority
email support. [product_faq.md]
(sources: product_faq.md)
```

To use your own documents, drop files into `data/sample_docs/` and re-run `ingest`.

## Configuration

All settings live in `.env` (see `.env.example`):

| Variable | Default | Meaning |
|---|---|---|
| `OPENAI_API_KEY` | — | **Required.** OpenAI API key |
| `EMBEDDING_MODEL` | `text-embedding-3-small` | Embedding model |
| `CHAT_MODEL` | `gpt-4o-mini` | Chat model |
| `CHUNK_SIZE` / `CHUNK_OVERLAP` | `800` / `120` | Recursive splitter settings |
| `TOP_K` | `4` | Chunks retrieved per question |

## Limitations & future work

- Keyword-free semantic search only — hybrid (BM25 + vector) retrieval would help exact-phrase queries.
- No conversation memory yet; each question is standalone.
- Single global index — per-user/per-tenant namespaces would be needed for multi-user use.
- Planned: reranking with a cross-encoder, streaming responses, a Streamlit UI.
